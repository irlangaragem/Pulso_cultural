                   Pulso Cultural               Plano de aprendizado &amp; implementação do MVP               Stack: React + Vite  ·  FastAPI  ·  OpenCV / YOLOv8  ·  PostgreSQL  ·  WebSocket                              Visão geral do sistema               O MVP tem três frentes técnicas que precisam se comunicar. Cada uma pode ser desenvolvida em paralelo, com um contrato de API acordado entre os times logo na semana 1.                                                      Visão Computacional               Python · OpenCV · YOLOv8 · Raspberry Pi / Jetson               Câmera na entrada do MAM. Detecta e conta pessoas em tempo real. Envia contagens para o backend via HTTP.                                Frontend               React + Vite · TypeScript · Tailwind · Zustand               Web app de check-in via QR code + guia digital da exposição + dashboard do gestor em tempo real.                                Backend               FastAPI · PostgreSQL · SQLAlchemy · WebSocket               API REST + WebSocket. Recebe dados da câmera e do check-in. Serve o dashboard. Gerencia LGPD e autenticação.                       Fluxo de dados:                 Câmera (Python)  →  POST /api/counts  →  FastAPI  →  WebSocket  →  Dashboard (React)                 Visitante (celular)  →  Web app React  →  POST /api/checkin  →  FastAPI  →  PostgreSQL                              Stack tecnológica                 Visão Computacional                                                   YOLOv8 (Ultralytics)                 ultralytics              yolov8n.pt               Modelo de detecção de objetos. Versão nano (yolov8n) roda em tempo real em hardware barato. Detecta pessoas com boa precisão mesmo em iluminação variável como a das galerias do MAM.                                   OpenCV                 opencv-python               Biblioteca de visão computacional. Captura frames da câmera, aplica o modelo YOLO e conta linhas de cruzamento (crossing line) para separar entradas de saídas.                                     Hardware recomendado                 Raspberry Pi 5              Jetson Nano               Raspberry Pi 5 (mais barato, roda YOLOv8n a ~10 FPS). Jetson Nano (mais rápido, melhor para ambientes com variação de luz). Câmera USB comum ou Pi Camera v3.                                   Persistência local                 SQLite              requests               Banco local leve para buffer de contagens quando a rede cai. Sincroniza automaticamente com o backend ao reconectar via requests (POST /api/counts).                                     Lógica de contagem                 line crossing              sort tracker               Algoritmo de linha virtual na entrada: pessoa cruzando de fora para dentro = entrada; de dentro para fora = saída. SORT tracker mantém identidade entre frames para evitar dupla contagem.                                   Sem armazenamento de imagens                 privacidade              LGPD               Nenhum frame é salvo. O processamento é local no dispositivo. Apenas o número de contagens e o timestamp são enviados ao backend.                         Frontend — React + Vite                                                   React + Vite + TypeScript                 react              vite              typescript               Vite como bundler (build muito mais rápido que CRA). TypeScript para tipagem das respostas da API. O web app precisa ser leve e abrir rápido em redes móveis no MAM.                                   Roteamento                 react-router-dom v6               Rotas: / (QR landing), /checkin (cadastro e retorno), /guia/:exposicaoId (guia digital), /dashboard (gestores). Rotas públicas e protegidas separadas.                                     Estado global                 zustand               Zustand para estado da sessão do visitante (CPF hasheado, exposição atual, passo do check-in). Mais simples que Redux para o escopo do MVP.                                   Estilização                 tailwindcss              shadcn/ui               Tailwind para utilitários. shadcn/ui para componentes acessíveis (input CPF, modal, toast). Fontes: Sora (títulos) e DM Sans (corpo), conforme brand do Pulso Cultural.                                     Comunicação com API                 axios              react-query               Axios para chamadas REST. React Query para cache e revalidação automática — especialmente útil no dashboard que atualiza com frequência.                                   WebSocket no dashboard                 native WebSocket              useEffect               Dashboard conecta via WebSocket ao FastAPI para receber contagens em tempo real sem polling. Hook customizado useOccupancy() encapsula a lógica de reconexão.                                     Geração do card compartilhável                 html-to-image              canvas               html-to-image converte um componente React em PNG para o share nativo do dispositivo (Web Share API). O card tem a identidade visual da exposição atual.                                   Player de áudio                 howler.js               Howler.js para o áudio guia: controle de play/pause, compatibilidade cross-browser, fallback para formatos. Áudio em streaming (não download) para economizar dados móveis.                         Backend — FastAPI                                                   FastAPI + Pydantic v2                 fastapi              pydantic              uvicorn               FastAPI pela documentação automática (Swagger UI em /docs), validação de dados com Pydantic e suporte nativo a async/await. Uvicorn como servidor ASGI.                                   Banco de dados                 postgresql              sqlalchemy 2              alembic               PostgreSQL para produção. SQLAlchemy 2 com modo async. Alembic para migrações de schema. Na câmera local, SQLite como buffer.                                     Autenticação                 python-jose              passlib              bcrypt               JWT para autenticação do dashboard dos gestores. python-jose para geração e validação de tokens. Nenhum login necessário no fluxo do visitante (check-in é pelo CPF).                                   Criptografia do CPF                 cryptography              hashlib               CPF nunca armazenado em texto puro. Hash com SHA-256 + salt único por instalação para identificação recorrente. Criptografia simétrica (Fernet) para dados que precisem ser recuperáveis.                                     WebSocket                 fastapi WebSocket              broadcaster               Endpoint /ws/dashboard transmite contagens em tempo real para o dashboard React. broadcaster como pub/sub entre worker processes em produção.                                   CMS para guias                 endpoints REST              SQLAlchemy               CRUD simples de exposições e obras via FastAPI. O gestor do MAM acessa uma interface admin (pode ser o próprio dashboard) para cadastrar e editar guias sem acessar código.                                     Exportação de relatórios                 reportlab              pandas + openpyxl               ReportLab para geração de PDF com layout visual. Pandas + openpyxl para exportação CSV/Excel dos dados agregados. Nenhum dado pessoal individual nos relatórios — só agregados.                                   Deploy                 docker              docker-compose              railway / render               Docker para containerizar a API e o banco. docker-compose para orquestrar localmente. Railway ou Render para deploy gratuito/barato adequado ao orçamento de espaços culturais.                                 Plano de aprendizado               O plano está dividido em três fases. As fases 1 e 2 são de aprendizado ativo — cada tecnologia estudada já produz um entregável real do projeto. A fase 3 é integração e deploy.                      Semana 0 — Setup e alinhamento               Antes de escrever uma linha de código, o time define o contrato entre as frentes. Isso evita retrabalho nas semanas seguintes.                                                    O que fazer na semana 0                                     Definir o contrato de API               Criar um documento (pode ser Notion ou README) com todos os endpoints acordados: POST /api/counts, POST /api/checkin, GET /api/dashboard/stats, GET /ws/dashboard. Cada frente sabe o que vai receber e o que vai enviar antes de começar a codar.                                     Setup do repositório               Monorepo no GitHub: pasta /frontend (React + Vite), /backend (FastAPI), /camera (Python). Um README na raiz explicando como rodar cada parte. Usar branches por feature e pull requests mesmo que seja um time pequeno.                                     Ambiente local de cada frente               Frontend: node 20+, npm, vite. Backend: Python 3.11+, uv ou pip, virtualenv. Câmera: Python 3.11+, OpenCV, torch. Cada pessoa roda o hello world da sua stack antes da semana 1.                                     Definir dados de mock               O backend cria endpoints falsos (mock) que retornam dados fixos. Frontend e câmera desenvolvem contra esses mocks e só integram de verdade na semana 4.                         Fase 1 — Fundação (Semanas 1 a 3)               Cada frente aprende sua stack construindo as funcionalidades centrais. O foco é ter algo funcionando — não perfeito. Fase 2 — Features completas (Semanas 4 e 5)               Com a base funcionando, cada frente finaliza as funcionalidades que faltam e começa a integração real — substituindo os mocks pelos endpoints de produção. S5                                 Calibração e validação. Testar em ambientes com iluminação variável. Ajustar threshold de confiança. Documentar precisão medida (% de acerto vs contagem manual). Dados pessoais nunca nos exports.                         Fase 3 — Integração e deploy (Semana 6)               As três frentes se conectam de verdade. O objetivo é ter o sistema funcionando end-to-end antes da instalação no MAM.                                                    Checklist da semana 6                                     Integração end-to-end               Câmera Python enviando POST /api/counts → FastAPI salvando → WebSocket notificando → Dashboard React atualizando em tempo real. Fazer esse fluxo funcionar completo em staging antes de ir ao MAM.                                     Testes de carga mínimos               Simular 200 visitantes fazendo check-in na mesma hora. FastAPI deve responder abaixo de 500ms. Usar locust (pip install locust) para gerar a carga. Ajustar connection pool do SQLAlchemy se necessário.                                     Deploy com Docker               Criar Dockerfile para FastAPI e docker-compose com postgres + api + worker. Deploy no Railway ou Render. Câmera: script de auto-start no boot do Raspberry Pi via systemd service.                                     Configurar variáveis de ambiente               Nunca subir senhas, chaves ou salt de criptografia no Git. Usar .env localmente e variáveis de ambiente na plataforma de deploy. Checar com git log que nenhum segredo vazou.                                     Visita técnica ao MAM               Instalar câmera no ponto de entrada do Solar do Unhão. Testar Wi-Fi no local. Calibrar linha de contagem com fluxo real. Posicionar QR code em local visível na entrada.                                     Plano de contingência               O que fazer se a câmera cair? (Buffer local + alerta por e-mail). E se o backend cair? (Câmera continua em modo offline). E se o Wi-Fi do MAM cair? (Câmera usa dados móveis via USB tethering como fallback).                                 Recursos de estudo recomendados               Todos gratuitos ou de acesso livre.
